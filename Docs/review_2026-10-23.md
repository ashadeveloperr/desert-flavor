## 3. 폴더 계층·코드 구조 (직접 고칠 수 있는가)

별도 에이전트가 읽기 전용으로 검토했고, 핵심 주장은 직접 다시 확인했다. 에이전트 지적 가운데 'CLAUDE.md 하루 90초'(이미 180초로 고쳐 있음)와 '새 UI에 샘플 배치 버튼 없음'(`BuildBarView.cs:58`에 있음)은 **사실이 아니어서 뺐다**.

### 3-1. 좋은 점 [확인]
- Core(규칙)는 `noEngineReferences`이고 `using UnityEngine`이 하나도 없다. 규칙과 표시가 분리돼 있다.
- 조정할 숫자는 대부분 `Assets/Data/Config/*.json`에 있다: 시설 비용·시간, 입찰자, 재해, 난이도 곡선, 하루 길이, 건설 배율.
- Core 테스트가 촘촘하다(EditMode 15파일, 회귀값 고정).
- `implementation_notes.md` 3절 '무엇을 바꾸려면 어디를 고치나' 표가 출발점으로 좋다.

### 3-2. 자주 할 작업의 난이도

| 작업 | 난이도 | 고칠 곳 |
|---|---|---|
| 시설 비용·시간 | 쉬움 | JSON `buildingLevels` |
| 입찰자 추가(기존 취향 종류) | 쉬움 | JSON `auction.bidders` |
| 난이도 곡선 | 쉬움 | `procedural_map_config.json` `difficulty` + `-- tune` |
| 새 플레이어 명령 | 중간 | `Settlement`의 Do*, `Settlement.Commands.cs`, `SaveGame.Apply`, UI 버튼(문서에 안내 있음) |
| 시설 모양 | 중간 | `FacilityModels.cs` 코드 숫자(눈으로 보며 고칠 수 없음 — 캡처 테스트로 확인 가능) |
| UI 배치·색 | 중간~어려움 | 색은 `UiKit.Theme`, 위치·크기는 각 View 코드 숫자. 수정 가이드 표에 UI 항목이 없음 |
| 새 재해 | 중간~어려움 | 약 5파일 |
| **새 시설 종류** | **어려움** | 약 8파일 12곳: JSON, `BuildingKinds`, `AllowedTerrain`, `BuildTool`, `FacilityInfo.KindName`, `BuildInputController.Label`, `FacilityModels`, `SettlementView` 색, `BuildBarView` 분류, 예전 `SettlementHud` 목록 |

## 4. 개선 제안 (우선순위)

| # | 작업 | 효과 | 규모 |
|---|---|---|---|
