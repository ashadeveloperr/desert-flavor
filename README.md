# 사막 정착지 경영 시뮬레이션 (Desert Settlement Simulator)

Unity 3D 헥스타일 기반 정착지 개발·생산망 최적화·경매 경영 게임의 **독립 프로토타입**입니다. 학원 수업용 Unity 저장소를 개인 계정으로 포크하여 새 프로젝트 작업용으로 정리했습니다. 《사막의 열병》 세계관을 사용하는 스토리 게임과는 별개의 프로젝트입니다.

> **현재 상태:** 기획 문서 통합 및 기본 Unity 프로젝트 정리 완료. 헥스맵·수로·건설·경매 **게임플레이 코드는 아직 구현되지 않았습니다.**

## 프로젝트 개요

- **게임 루프:** 지역 정보 → 장비 선택 → 정착지 건설·운영 → 경매 → 매각/보류 → 매각 대금으로 장비 강화 및 다음 지역 개척
- **맵:** 반경 3~7의 3D 헥스타일(37~169타일), MVP 37타일
- **수로:** 시설은 육각형 타일 내부, 수로는 **변(Edge)**, 분기점은 **꼭짓점(Vertex)**. 인접 수로로 시설 자동 취수
- **물 배분:** 상류 시설 우선, 동일 공급 순위는 물 수요 비례 배분; 하류만 물탱크 급수
- **시간:** 1배속 게임 내 하루 90초, 경매장 완공 후 첫 경매까지 4일, 이후 4일 주기
- **작업:** 건설·철거·개량 작업 슬롯 2개, 개량 중 가동 중단, 착공 후 취소 시 투입 석재 50% 반환
- **자원:** 식량·석재·광물·물·자금. 일반 생산시설의 물 가동률 × 식량 전역 계수 = 실제 가동률. **우물 생산량은 식량 계수에서 제외(확정)**
- **건설·경매·재고:** 건설비는 **석재만** 사용, 경매 가치는 **직전 24게임시간 실제 생산**, 매각 시 **식량·석재는 현장에 남음** (세 가지 모두 확정)
- **수익:** 광업 생산 기반의 정착지 가치 × 식량·석재·인프라 배율. 매각금 100% 플레이어 귀속
- **MVP:** 두 개 이상의 정착지를 순차 개발·매각하는 핵심 루프 구현

## Unity 프로젝트 열기

1. Unity Hub에서 저장소의 루트 폴더를 프로젝트로 추가합니다.
2. **Unity 6 / 6000.3.15f1** (포크의 `ProjectSettings/ProjectVersion.txt`에 기록된 에디터 버전)으로 열어 주세요. 설치 버전이 다르면 패키지 재해석·업그레이드가 발생할 수 있습니다.
3. `Assets/Scenes/SampleScene.unity`에서 시작합니다. 이 씬은 **기존 빈 기본 씬**이며 게임플레이를 구현한 씬이 아닙니다.
4. 렌더링 설정은 기존 URP 관련 `Assets/Settings`, `Packages`, `ProjectSettings`를 유지했습니다. Unity 최초 실행 시 패키지 복원 및 재임포트가 필요할 수 있습니다.

## 정리 내역 및 안전 장치

- 개인 포크에만 적용한 정리입니다. 원본 `KooHoo-Dev` 조직 저장소는 변경하지 않았습니다.
- 원래 수업용 예제·대용량 외부 에셋·레거시 코드·IDE 설정은 메인 브랜치에서 제거했습니다.
- 정리 전 상태는 **[`backup/original-unity-course-2026-10-20`](../../tree/backup/original-unity-course-2026-10-20)** 브랜치에 보존했습니다.
- Unity의 `Assets` 폴더 밖에 기획문서를 두어 Unity Import에 불필요하게 포함되지 않도록 했습니다.
- 작업 시작 후 Unity에서 프로젝트와 URP를 실제 실행·검증한 뒤 새 게임 코드를 추가하세요.

## 포크와 조직 원본에 대한 주의

- **Contribute → Open pull request:** 개인 포크의 변경 내용을 **조직 원본에 제안**합니다. 조직 권한자가 병합하기 전에는 원본이 바뀌지 않습니다.
- **Sync fork:** 원본 저장소의 최신 커밋을 **내 포크로 가져옵니다**. 원본을 덮어쓰지 않습니다.
- **중요:** 이 포크는 수업 자료를 대량 제거해 전용 게임 프로젝트로 전환했으므로, 현재의 정리 커밋을 조직 원본에 그대로 PR로 보내면 원본에서도 수업 파일을 지우는 변경을 제안하게 됩니다. 원본에 반영하려면 관리자의 사전 동의 아래 **공유할 코드·문서만 분리한 별도 PR**을 만들 것을 권장합니다.
